# HU-001: Carga y validación de datos de estudiantes

## Descripción (del documento)

Como integrante del Área de Sistemas de Información, quiero cargar en la plataforma la
exportación de datos académicos y socioeconómicos de los estudiantes para que el modelo
trabaje con información completa y validada, sin modificar el sistema de gestión
académica.

## Criterios de aceptación (del documento)

1. Dado que el archivo exportado tiene la estructura esperada, cuando el Área de Sistemas
   lo carga, entonces la plataforma incorpora los datos e informa la cantidad de
   estudiantes cargados.
2. Dado que al archivo le falta una columna obligatoria o tiene otro formato, cuando se
   intenta cargarlo, entonces la plataforma rechaza la carga completa e indica qué
   columnas presentan el problema.
3. Dado que algunos registros tienen valores faltantes o fuera de rango, cuando se carga el
   archivo, entonces esos registros no se incorporan y se listan en un informe de errores.
4. Dado que la exportación puede incluir datos identificatorios, como nombre o documento,
   cuando se incorporan los datos, entonces cada estudiante queda identificado con un
   código seudonimizado y se descartan las variables que el modelo no utiliza.
5. Dado que la carga corresponde a un momento del período académico (inscripción, cierre
   del primer semestre o cierre del segundo), cuando se registra, entonces queda asociada
   a ese momento.

## Notas de implementación

- **1.2:** tablas del DER con SQLAlchemy 2 (declarativo) y creación al iniciar
  (`create_all`) más datos iniciales (roles y usuarios de prueba). Sin Alembic, salvo que
  el usuario lo pida.
- **Generar las cargas simuladas** con un script (`scripts/generar_cargas.py`) a partir de
  la partición guardada: solo estudiantes de **prueba**, identificadores sintéticos,
  formato de la decisión P2.
- **Columnas obligatorias** según el momento: las de `VARIABLES_POR_MOMENTO[momento]` más
  `legajo`. Las identificatorias y excluidas pueden venir y se descartan.
- **Rangos**: definirlos a partir del análisis exploratorio (por ejemplo, edad 15 a 80,
  notas del semestre 0 a 20, nota del título previo 0 a 200, binarias 0/1, categóricas
  dentro de los códigos conocidos). Ponerlos en un único lugar (`datos/validacion.py`).
- **Informe de errores**: CSV descargable con fila, legajo seudonimizado (nunca el legajo),
  columna y motivo.
- **Seudonimización** (confirmada el 03/11): `EST-` + 8 hex en mayúscula del HMAC-SHA256
  del legajo con `SEUDONIMO_CLAVE`. El legajo, documento y nombre no se guardan en ningún
  lado, tampoco en logs. Si dos legajos distintos de una misma carga dan el mismo código
  (muy improbable), la carga se rechaza con un mensaje claro en lugar de mezclarlos.
- **Momentos sucesivos**: si el estudiante ya existe (carga anterior), no se duplica: se
  agrega su RENDIMIENTO_SEMESTRE del nuevo momento.
- El archivo original no se conserva después de procesarlo.
- La carga termina con una señal (función o evento) que HU-003 usa para disparar el
  recálculo. En esta historia basta con dejar el punto de enganche.

## Pruebas por criterio

| Criterio | Prueba |
|---|---|
| 1 | Cargar el archivo de inscripción válido → N estudiantes incorporados e informados |
| 2 | Archivo sin una columna obligatoria (y otro separado por «,» o con tipos de texto) → carga rechazada completa, mensaje con las columnas |
| 3 | Archivo con 3 registros con faltantes o fuera de rango → se incorporan N−3 y el informe lista los 3 |
| 4 | Después de cargar: ninguna tabla tiene legajo, documento, nombre ni variables excluidas; los códigos tienen el formato `EST-XXXXXXXX` y el mismo legajo da el mismo código |
| 5 | La fila de CARGA tiene el momento elegido y el usuario de prueba |

Archivos de prueba con errores en `tests/fixtures/`.
