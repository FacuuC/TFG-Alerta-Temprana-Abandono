# HU-007: Registro del estado de seguimiento

## Descripción (del documento)

Como tutor/a, quiero registrar el estado de seguimiento de cada alerta (pendiente,
contactado o en acompañamiento), para que el Programa de Tutorías sepa qué casos ya fueron
atendidos.

## Criterios de aceptación (del documento)

1. Dado que se generó una alerta, cuando aparece por primera vez, entonces su estado es
   «pendiente».
2. Dado que el tutor contactó al estudiante o inició el acompañamiento, cuando cambia el
   estado a «contactado» o «en acompañamiento», entonces el nuevo estado se guarda con la
   fecha y el usuario que lo registró.
3. Dado que el estado de una alerta cambió, cuando otro usuario del Programa de Tutorías
   consulta el listado, entonces ve el estado actualizado.
4. Dado que el riesgo del estudiante se recalcula, cuando se actualiza la alerta, entonces
   se conserva el estado de seguimiento registrado.

## Notas de implementación

- Función `cambiar_estado(id_alerta, estado_nuevo, id_usuario)` que actualiza ALERTA y
  agrega una fila en CAMBIO_ESTADO (anterior, nuevo, usuario, fecha) en una transacción.
  Ruta `POST /api/alertas/{id}/estado`.
- Estados válidos: `pendiente`, `contactado`, `en_acompanamiento` (se muestran como
  «Pendiente», «Contactado», «En acompañamiento»).
- Usuario: el usuario de prueba elegido en la barra superior (P5).
- Listado: desplegable por fila. Ficha: desplegable + «Guardar estado» + «Alerta creada el…».

## Pruebas por criterio

| Criterio | Prueba |
|---|---|
| 1 | Alerta nueva → «pendiente» |
| 2 | Cambio a «contactado» → ALERTA actualizada y fila en CAMBIO_ESTADO con usuario y fecha |
| 3 | Después del cambio, `consultar_alertas` devuelve el nuevo estado |
| 4 | Cambio a «en acompañamiento», nueva carga que recalcula → el estado sigue igual |
